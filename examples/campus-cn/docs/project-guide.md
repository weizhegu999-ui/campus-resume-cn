# 项目说明与面试指南

## 项目目标

围绕中文校招，把“填完简历”进一步变成“整理可解释的经历”：使用中文 A4 模板，以 STAR 结构补全项目过程，对照目标岗位 JD 查看文字覆盖情况，并在本地保存草稿、交换 JSON、打印 PDF。

项目在 Reactive Resume 的源码与 Git 历史中新增独立前端示例，实际复用上游默认数据与项目过滤规则的 vendor 快照。中文界面、草稿模型、导入导出适配、岗位词典、写作规则及浏览器打印由本示例实现；没有运行完整上游账号系统、服务端或 Forme PDF 渲染链路。

## 先确认自己能说明哪些部分

面试前实际运行项目，阅读对应源码，改一处规则，再验证结果。只把自己能解释、能操作、能排查的部分写为个人工作。可按以下模块准备：

| 模块           | 应能解释的问题                                           | 可现场演示的证据                     |
| -------------- | -------------------------------------------------------- | ------------------------------------ |
| 中文表单与预览 | 编辑状态如何映射到预览？用户输入如何作为文本安全显示？   | 修改项目行动，观察预览同步变化       |
| STAR 项目编辑  | 为什么分开背景、任务、行动和结果？如何避免凭空添加成果？ | 用真实材料补全过程，保留未确认项     |
| JD 词典匹配    | 术语怎样识别、如何归一化？分子分母是什么？有哪些误差？   | 修改 JD，核对覆盖项与缺失项          |
| JSON 适配      | 本示例数据与上游数据哪里不同？为什么导入不是无损的？     | 导出、重新导入，对照字段与隐藏条目   |
| 草稿与隐私     | `localStorage` 按什么范围隔离？清除站点数据会怎样？      | 刷新恢复草稿，导出备份后清除本站数据 |
| A4 与打印      | CSS 毫米单位、打印样式与屏幕预览如何配合？               | 改长内容，检查溢出与打印分页         |
| 本地服务       | 为什么仅绑定回环地址？为何需要资源白名单和真实路径检查？ | 查看允许资源，确认隐藏目录返回 404   |
| 上游复用       | 哪些文件直接复用？来源、版本与许可怎样追踪？             | 运行 vendor 来源校验并查看第三方声明 |

## 可以怎样介绍

掌握并亲自验证相关模块后，可按事实调整下面的描述：

> 在 Reactive Resume 的开源代码基础上新增中文校招前端示例，复用上游默认简历数据和条目过滤规则，完成中文 A4 模板、STAR 结构化编辑、岗位 JD 本地词典匹配、JSON 交换与浏览器打印适配。通过核心规则测试和浏览器交互检查验证导入边界、隐藏内容处理与打印表现。

上面是**项目能力描述模板**。不能因为代码存在，就自动将每个模块写成自己独立完成。应把“完成”改成符合实际的“阅读并修改”“参与实现”“实现并验证”或“基于现有代码扩展”，并保留能说明的具体修改与验证记录。

如用于电气专业求职，可强调面向电气类岗位词汇的结构化整理需求，并举真实课程设计或仿真项目作为输入材料。工具本身是软件项目，不自动证明继电保护整定、现场调试、工程设计或实习经历。内置电气简历是虚构演示数据。

## 设计取舍

- **独立示例与上游复用**：保留上游来源和固定 vendor 快照，让复用边界可核对；新界面独立运行，减少完整后端的配置成本。代价是没有继承上游全部功能。
- **原生 ESM 与零运行依赖**：浏览器直接加载模块，Node.js 标准库提供本地服务；部署简单，源代码便于追踪。代价是表单、状态和渲染需要自行维护。
- **可解释词典匹配**：展示术语与覆盖证据，方便测试和复核；没有模型调用成本。代价是无法充分理解上下文、否定句、所有同义表达和真实招聘规则。
- **本地草稿**：无需账号即可使用，不自动发送内容。代价是没有跨设备同步，浏览器站点数据被清理后需要依靠导出备份恢复。
- **浏览器打印 PDF**：复用浏览器能力，不额外启动渲染服务。代价是字体、浏览器和打印设置会改变分页，需要人工检查。
- **上游 JSON 子集适配**：使用完整默认对象填入已支持字段，明确告知丢失范围。代价是无法保证任意上游文档往返无损，必须保留原始文件。

## 验证应怎样表达

在示例目录运行：

```powershell
node --test tests/*.test.js
node scripts/sync-upstream.mjs --check
node scripts/serve.mjs
```

记录真实执行结果，再手动检查编辑、刷新恢复、JSON 导入导出、JD 覆盖证据、窄屏布局和打印预览。用极长文本、空输入、无词典命中的 JD、隐藏条目和不支持的上游字段检查边界。

只有实际完成后，才能写“测试通过”“已部署”或列出准确数量。自动规则测试不能替代打印分页检查；局部示例通过也不能代表完整上游前后端、数据库和账号流程均已验证。

## 限制与可继续扩展的方向

当前匹配分数是词典覆盖率，不是面试邀请概率、人才能力分或 ATS 官方得分。写作建议是规则结果，复制的 AI 提示词是供用户自行使用的文本；没有接入真实模型。

可继续做的工作包括更严格的字段校验、词典维护界面、更细的术语证据、更多中文打印样式、上游 JSON 兼容测试，以及在用户明确同意后接入模型 API。若新增模型功能，需要解释发送哪些字段、如何处理密钥、失败时怎样回退，并用真实请求验证；不能只增加按钮就把功能描述为 AI 优化。

介绍项目时，明确说出“复用哪些上游成果、自己改了什么、怎样验证、目前有什么限制”。能现场讲清一个具体取舍，比罗列未掌握的技术栈更可信。
