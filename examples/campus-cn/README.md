# 中文校招简历工作台

在 Reactive Resume 源码与 Git 历史中新增的独立中文校招示例。用中文 A4 模板、STAR 项目编辑、岗位 JD 词典匹配和本地草稿，帮助学生把真实经历整理成可以复核、可以解释的简历。

本目录可单独运行，零运行依赖，使用原生 JavaScript ES modules。它复用上游默认简历数据和项目过滤规则的固定快照；新增界面、简历模型和浏览器打印流程位于本目录。完整上游 React 前端、服务端、账号、数据库和 PDF 渲染服务未在本示例中启动。

## 本地运行

需要 Node.js 24 或更新版本。无需在仓库根目录执行 `pnpm install`，无需安装本目录的依赖。

```powershell
cd E:\错题\campus-resume-cn\examples\campus-cn
node scripts/serve.mjs --open
```

也可在当前目录运行 `npm start`，或 Windows 下双击 `启动.cmd`。启动脚本先查找 PATH 中的 Node.js，再尝试已有的 Codex 本地 Node.js 运行时路径。默认地址为 `http://127.0.0.1:4174`；端口占用时依次尝试之后的 10 个端口，以终端实际输出为准。省略 `--open` 可只启动服务、不自动打开浏览器。终端按 `Ctrl+C` 停止。

修改起始端口：

```powershell
$env:PORT = '4184'
node scripts/serve.mjs
```

服务仅监听本机 `127.0.0.1`，用于本地预览。它只提供入口文件、样式和 `src`、`vendor`、`assets`、`docs` 静态资源，拒绝 `.git`、环境文件、测试、脚本目录及路径穿越请求。公开发布应使用静态托管平台，而不是把本地服务暴露到公网。

## 功能与使用顺序

1. 选择中文校招模板，编辑联系方式、教育经历、技能、经历与奖项。
2. 把项目拆成背景、任务、行动、结果，保留自己能解释的过程和证据。内置电气专业内容是虚构示例，不能直接当作个人履历。
3. 粘贴目标岗位 JD，查看本地词典识别的要求、已覆盖项、缺失项和匹配证据。
4. 根据可核实的事实修订简历，查看 A4 预览与内容溢出提示。
5. 导出 JSON 备份，或通过浏览器打印保存 PDF。

匹配分数只是**词典识别到的 JD 术语中，简历文字已覆盖术语的比例**。它不代表招聘概率、能力评价或真实 ATS 排名；同义词、上下文、否定语义和未收录术语可能影响结果。请直接核对匹配证据，不要为了加分编造技能。

写作建议由本地规则生成。可复制的 AI 润色提示词只是文本，复制后需要自行选择工具使用；本示例未接入模型、没有自动调用 AI，也不自动把简历发送给其他服务。

## 打印并保存 PDF

1. 在预览中检查姓名、联系方式、项目内容及溢出提示，先删减无关内容。
2. 使用页面的打印功能，在浏览器打印对话框中选择“另存为 PDF”。
3. 纸张选择 **A4**，缩放/比例选择 **100%**，关闭“页眉和页脚”，方向选择纵向。可启用“背景图形”保留模板配色。
4. 检查打印预览的分页、中文字体与内容完整性，再保存文件。

打印采用浏览器的 CSS 排版。不同浏览器、字体和打印设置会改变换行与页数；A4 预览和溢出提示用于辅助检查，不保证任意长内容都能放进一页。此处没有使用上游 Forme PDF 渲染器。

## JSON 交换与兼容边界

- **本示例 JSON**：用于保存和重新导入本示例支持的草稿字段，适合继续编辑。
- **Reactive Resume v6 JSON**：以复用的完整上游默认数据为底稿，写入本示例支持的联系方式、教育、项目、经历、技能与奖项字段，便于向上游编辑器交换数据。
- **导入上游 JSON**：只转换支持的字段子集，不能无损编辑任意上游文档。照片、自定义字段与章节、个人链接、语言、兴趣、证书、论文、志愿活动、推荐人、求职信、复杂格式和原布局等内容不会完整保留。富文本会转成纯文本。

隐藏项目保持隐藏；本示例不支持单项可见性控制的其他章节会略过隐藏条目。中文预览模板导出时映射为上游支持的 `onyx` 模板和兼容布局信息，重新导入上游后外观不会与本示例一致。交换前请保留原始 JSON。具体列表与代码来源见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## 隐私与草稿

编辑内容保存在当前浏览器、当前站点的 `localStorage`。无需注册，应用代码不自动上传简历、JD 或草稿，也不包含遥测和第三方字体请求。导出文件由浏览器下载到本机；复制提示词后的后续使用由你自行决定。

清除草稿前建议导出 JSON。需要彻底清除时，可在浏览器的站点数据设置中删除本站数据，或在开发者工具的 Application/存储面板删除本站 `localStorage`。清理浏览器数据、使用无痕模式、切换浏览器或切换端口可能使原草稿不可用。共享设备应在使用后清除本站数据。

## 技术架构

| 位置                          | 职责                                                         |
| ----------------------------- | ------------------------------------------------------------ |
| `index.html`、`styles.css`    | 中文编辑界面、A4 预览、响应式布局与打印样式                  |
| `src/*.js`                    | 草稿模型、JSON 适配、STAR 编辑、词典匹配、DOM 交互与本地存储 |
| `vendor/reactive-resume/*.js` | 上游默认数据和过滤规则的固定、可验证快照                     |
| `scripts/sync-upstream.mjs`   | 按固定上游 Git 提交生成或核对 vendor 快照与来源摘要          |
| `scripts/serve.mjs`           | 仅使用 Node.js 标准库的本地静态服务                          |
| `tests/*.test.js`             | 使用 Node.js 内置测试运行器验证核心规则与边界                |

不引入框架或打包器，是为了让独立示例可直接运行和静态部署。代价是需要自行维护 DOM 状态同步、字段验证和浏览器打印差异。完整上游应用的安装方式仍以仓库根目录文档为准。

## 验证命令

从本目录运行：

```powershell
node --test tests/*.test.js
node scripts/sync-upstream.mjs --check
```

或者运行 `npm test`。Node.js 24 的测试运行器可以直接展开上述通配符，Windows 不依赖 shell 展开。测试只覆盖实际写出的用例；浏览器交互和打印分页还需要实际检查。此文档不把未运行的完整上游构建、后端测试或外部部署计为已验证。
